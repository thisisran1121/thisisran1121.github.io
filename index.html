PROJECT 01
부동산 시세 데이터 기반
이기종 DB 구축 및 마이그레이션
2025.04 · SeSAC 용산4기 팀 프로젝트 (6인)
Oracle 19c PostgreSQL 17 Rocky Linux SQL*Loader ora2pg HammerDB
배경 / 문제
공공데이터 포털의 아파트 매매 실거래가 데이터(대규모 CSV)를 Oracle과 PostgreSQL 두 DBMS에 각각 적재하고, 두 환경 간 양방향 마이그레이션을 실현하여 이기종 DB 운영 역량을 실무 수준에서 검증하는 것이 목표였습니다.

각 팀원이 독립 Linux 서버를 할당받아 처음부터 DBMS 환경을 직접 구축해야 했습니다.
담당 역할 및 수행 내용
OS / DBMS 인프라 구축 전담:
• LVM으로 디스크 파티션 구성, 파일시스템 마운트
• 커널 파라미터 튜닝 (shmmax, semaphore 등)
• Oracle SGA/PGA, PostgreSQL shared_buffers / work_mem 설정
• Transparent HugePages 비활성화 + HugePages 수동 할당

데이터 적재 및 마이그레이션:
• Oracle: Staging → Final 테이블 설계, SQL*Loader CTL 파일 작성
• PostgreSQL: COPY 명령 기반 CSV 대용량 적재
• PostgreSQL → Oracle: pg_dump → CSV → SCP → SQL*Loader
• Oracle → PostgreSQL: ora2pg DDL 생성 → 데이터 추출 → 검증
트러블슈팅
① TNS 연결 오류
tnsnames.ora SID/서비스명 불일치로 ora2pg 연결 실패. tnsping으로 경로 확인 후 TNS_ADMIN 환경변수를 재지정하여 해결.

② DATE 타입 불일치
PostgreSQL의 DATE는 날짜만, Oracle의 DATE는 시분초 포함. CTL 파일에서 TO_DATE 마스크를 명시적으로 지정하여 적재 오류 해결.

③ VARCHAR2 BYTE/CHAR 처리
한글 데이터에서 BYTE 의미론 적용 시 바이트 초과 오류 발생. 테이블 컬럼 정의를 VARCHAR2(n CHAR)로 수정하여 해결.

④ 시퀀스 충돌
마이그레이션 후 INSERT 시 기존 시퀀스값 충돌. 대상 시퀀스를 최댓값 +1로 ALTER SEQUENCE 재설정.
성과 / 결과
Oracle ↔ PostgreSQL 양방향 마이그레이션을 데이터 정합성 100% 검증 완료. 두 DBMS의 메모리 아키텍처 차이를 실무 수준에서 체득하며 DBA적 사고방식을 확립했습니다.

PROJECT 02
Prometheus + Grafana 기반
이기종 DB 통합 모니터링 시스템 구축
2025.04 · SeSAC 용산4기 팀 프로젝트
Prometheus Grafana oracledb_exporter postgres_exporter systemd
배경 / 문제
Oracle과 PostgreSQL 서버가 각각 분리된 서버에서 운영되는 환경에서, 두 DB의 실시간 지표(CPU, Memory, Tablespace, 세션 수 등)를 단일 대시보드에서 통합 모니터링할 수 있는 환경이 필요했습니다.

별도의 모니터링 전용 서버를 구성하여 Pull 방식의 수집 아키텍처를 설계했습니다.
수행 내용
모니터링 아키텍처 설계:
• 전용 모니터링 서버에 Prometheus 설치 및 prometheus.yml 구성
• Grafana 설치 → 데이터소스 Provisioning 자동화

DB 서버 Exporter 배치:
• Oracle: oracledb_exporter + 모니터링 전용 계정 생성, Custom Metrics YAML 작성
• PostgreSQL: postgres_exporter + pg_stat 기반 Custom Queries 구성
• 각 Exporter를 systemd 서비스로 등록하여 자동 재시작 보장

Grafana 대시보드:
• Oracle / PostgreSQL 각각의 지표를 패널로 구성
• Tablespace 사용률, 세션 수, 쿼리 TPS, 메모리 사용률 시각화
트러블슈팅
① oracledb_exporter 연결 실패
Oracle Instant Client 경로 미설정으로 exporter 기동 실패. LD_LIBRARY_PATH와 ORACLE_HOME을 systemd 서비스 파일의 Environment=에 직접 명시하여 해결.

② Grafana 데이터소스 자동 인식 불가
Provisioning YAML 파일 위치 및 권한 문제. /etc/grafana/provisioning/ 경로 확인 후 grafana 사용자 소유로 수정하여 재기동 시 자동 로드 확인.
성과 / 결과
Oracle과 PostgreSQL 2개 DBMS를 단일 Grafana 대시보드에서 실시간으로 통합 모니터링하는 환경 구축 완료. Custom Metrics를 통해 범용 exporter로는 수집되지 않는 Tablespace 사용률과 DB-specific 지표를 추가 확보.
